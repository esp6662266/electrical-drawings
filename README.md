# 전기도면

## v1.4.1 · 검색 검토 후 개선

태그의 띄어쓰기(`14KA 10`, `14 KA 10`)와 `% I 0.0`, `14KA10은 무슨 기능인지` 같은 요청을 처리합니다. 실제 도면 본문을 매뉴얼보다 먼저 표시하고, 매뉴얼 목차·절 번호가 일치한 결과와 파일명만 일치한 결과를 구분합니다. 서로 다른 번호나 물리 기능을 추정하여 연결하지 않습니다.

배포용 색인의 공통 원본 정보 중복을 줄여 JSON을 약 18.3MB에서 11.8MB로 축소했습니다(약 35.6%, gzip 기준 약 9.1%). 사진 6건은 별도의 작은 파일에서 먼저 표시합니다. 검색어가 없거나 기능 설명만 찾을 때 큰 색인을 받지 않으며, 사진 전용 검색은 사진 자료만 읽습니다. 정상 수신한 자료는 유지하고 실패한 부분만 다시 읽습니다. 로딩/부분 실패를 검색 결과 없음으로 확정하지 않습니다.

본문 전체는 펼칠 때만 생성하고, 반복 검색은 원본 문자열의 정규화 결과를 재사용합니다. 검색 초기화·링크 복사·화면 이동 후 검색어 유지를 지원하며 한글 조합 중 Enter는 미완성 검색을 실행하지 않습니다. 모바일은 메뉴·설비 목록을 접고 검색창을 먼저 보여줍니다.

## v1.4.0 · I/O·단자·배선 검색

왼쪽 메뉴의 **I/O·단자·배선 검색**에서 태그(`14KA10`), 배선 번호(`8.9`, `8.10`, `13.6`), PLC 주소(`X010`, `I/15`)와 기능을 검색합니다. 설비·자료 구분 필터, 일치 부분 강조, 원본 PDF 페이지/추출 본문 바로가기, 검색 링크 재열기를 지원합니다. 여러 번호를 공백·쉼표로 입력하면 어느 하나가 포함된 결과를 보여줍니다. `8.10`과 `8.1`, `14KA10`과 `15KA10`은 다른 식별자입니다.

등록된 I/O·HMI·신호·알람 설명은 현재 브라우저의 설비 정의에서 읽으며 기존 자료를 수정하지 않습니다. 원본 본문 색인은 빌드 때 `scripts/build-io-search-index.mjs`로 생성하고 검색 화면에서만 불러옵니다. 공개 제외 원본과 PLC 바이너리 문자열은 색인하지 않습니다. 추출 텍스트가 없는 스캔·사진·전용 파일은 본문 검색 대상에서 빠지며, 검색 결과가 없다는 이유로 미등록 기능을 추정하지 않습니다.

사용자 제공 사진의 판독 표기는 `data/io-reference-notes.json`에서 별도로 관리합니다. `14KA10`의 함체 라벨은 `EMERGENCY DRIVE CIRCUIT08`, `14KA8`은 `EMERGENCY MCC CIRCUIT02`입니다. `14KA6`의 기능과 `8.9·8.10·13.6`의 단자대/연결 기능은 미확정입니다. 사진은 설비에 임의 배정하지 않았으며 `15KA10`을 `14KA10`의 별칭으로 등록하지 않았습니다.

## 시작하기

사이트의 **설비 등록·프로젝트 백업**에서 ID와 설비명을 등록합니다. 등록한 설비를 선택하면 같은 화면에서 매뉴얼·진단·수리·수리 기록·I/O·HMI·제어 명세·래더·호출·신호 구조·도면·시험·확인 대장을 정리할 수 있습니다. **선택 설비의 자료 편집**에서 JSON 양식에 내용을 입력합니다. [입력 항목](templates/README.md)을 참고하세요.

설비·기록은 현재 브라우저/호스트의 로컬 저장입니다. **프로젝트 전체 JSON**에는 설비 정의와 기록이 함께 포함됩니다. 기존 **모든 설비 통합 백업·복원**은 메모·수리 기록만 포함하므로 다른 기기에서는 먼저 해당 설비 정의를 등록해야 합니다. 참조 PDF·이미지 파일 자체와 작성 중인 초안은 JSON 백업에 포함하지 않습니다. 파일 원본은 별도로 보관하세요.

공유 게시 자료는 `data/project.js`에서 관리합니다. 사이트에서 **공유용 project.js 다운로드** 후 이 파일을 교체하고 GitHub에 커밋하면 Netlify에서 재배포합니다. 이 파일에는 설비·자료 정의만 포함하며 개인 메모·수리 기록을 포함하지 않습니다. 도면 등은 프로젝트 내 자료 폴더에 넣고 참조 경로를 등록합니다. 공개 저장소에 올리기 전 공개 가능한 자료인지 확인하세요.

## 복사 범위

GME의 원본 HTML 구조와 CSS, 설비 탭 구성을 유지했습니다. 메모 검증, 충돌 처리, 수리 기록 보조 도구, 통합 백업·복원 코드를 복사해 독립 프로젝트 이름으로 분리했습니다. GME에 고정된 설비별 렌더러는 범용 빈 양식 렌더러로 교체했습니다. 원본 화면/렌더러 참조본은 `reference/`에 있으며 게시 대상에서 제외합니다.

GME의 원본 도면·PLC·설비 데이터·과거 게시/검증 기록·시뮬레이터·인증 세션·자료실 데이터는 포함하지 않습니다. 기존 GitHub 저장소와 Netlify 프로젝트는 변경하지 않았습니다. 로그인 자료실 서버는 빈 프로젝트에 활성화하지 않았으며 이 버전은 브라우저 저장형 작업실입니다. 실제 PLC 통신·운전·설정 변경·시뮬레이터 실행 기능은 없습니다.

## 개발·배포

Node.js 22 이상. 추가 패키지 설치 없이 `node --test tests/*.test.mjs`, `node scripts/build.mjs`, `node scripts/serve.mjs`를 실행합니다. 미리보기는 http://127.0.0.1:8786 입니다. Netlify에서 이 저장소의 `main`을 연결하고 `netlify.toml`을 사용합니다. 빌드마다 테스트 후 `dist`만 게시합니다. `reference/`·테스트·이전 GME 원본은 게시하지 않습니다.
